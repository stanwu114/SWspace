## 一、文档概述

### 1.1 文档目的

本文档定义了"AI员工协作系统"的技术架构，为开发团队提供统一的技术指导和实施依据。

### 1.2 适用范围

- 开发团队成员
- 技术评审人员
- 后续维护人员

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| AI员工 | 基于大语言模型的智能Agent，具有特定角色和专业能力 |
| LTC | Lead to Cash，华为销售流程框架 |
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| Agent | 智能代理，能够自主规划和执行任务的AI实体 |

## 二、系统背景与目标

### 2.1 业务背景

面向政企智慧城市行业的**"超级个人 + AI员工团队"**协作系统，让资深行业专家能够以一人之力，借助AI员工团队完成原本需要完整销售团队才能完成的工作。

### 2.2 核心目标

| 目标 | 描述 | 衡量指标 |
|------|------|----------|
| 文档产出效率 | AI辅助生成方案、标书、报告 | 提升50%+ |
| 信息处理效率 | AI自动监控、解读招标/政策信息 | 提升100%+ |
| 客户跟进质量 | AI管理客户画像、提醒跟进 | 漏跟进率下降80% |
| 知识复用效率 | AI沉淀案例、经验、最佳实践 | 知识库调用频次提升200% |

### 2.3 系统边界


## 三、架构设计原则

### 3.1 核心原则

| 原则 | 说明 | 实践方式 |
|------|------|----------|
| **本地优先** | 敏感数据不出本地 | 客户信息、合同等本地加密存储 |
| **AI增强** | AI作为增强工具而非替代 | 用户始终拥有最终决策权 |
| **模块解耦** | 各模块独立，低耦合 | 清晰的模块边界和API接口 |
| **渐进增强** | 基础功能简单，高级功能按需 | 渐进式披露设计 |
| **可扩展** | 预留扩展能力 | 插件化Agent、可配置工作流 |

### 3.2 架构约束

| 约束 | 说明 |
|------|------|
| 技术栈约束 | 前端Electron+React，后端Java（AgentScope+Spring Boot） |
| 部署约束 | 纯本地部署，不依赖云服务 |
| 安全约束 | 敏感数据全部加密存储 |
| 用户约束 | 单用户单实例 |

### 6.2 核心表结构

#### 6.2.1 projects（项目表）

```sql
CREATE TABLE projects (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name            VARCHAR(200) NOT NULL,
    code            VARCHAR(50),                    -- 项目编号
    customer_id     UUID REFERENCES customers(id),
    status          VARCHAR(20) NOT NULL DEFAULT 'lead',  -- lead/opportunity/execution/completed/cancelled
    stage           VARCHAR(50),                    -- 详细阶段
    estimated_value DECIMAL(15,2),
    contract_value  DECIMAL(15,2),                  -- 成交金额
    bid_deadline    TIMESTAMP,
    contract_date   DATE,                           -- 签约日期
    description     TEXT,
    requirements    JSONB,                          -- 结构化需求
    tech_stack      JSONB,                          -- 技术栈
    risk_assessment JSONB,                          -- 风险评估
    tags            JSONB DEFAULT '[]',             -- 标签数组
    created_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    created_by      VARCHAR(100),
    
    CONSTRAINT chk_status CHECK (status IN ('lead', 'opportunity', 'execution', 'completed', 'cancelled'))
);

-- 索引
CREATE INDEX idx_projects_customer ON projects(customer_id);
CREATE INDEX idx_projects_status ON projects(status);
CREATE INDEX idx_projects_deadline ON projects(bid_deadline);
CREATE INDEX idx_projects_created ON projects(created_at DESC);
```

#### 6.2.2 customers（客户表）

```sql
CREATE TABLE customers (
    id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name               VARCHAR(200) NOT NULL,
    short_name         VARCHAR(100),                -- 简称
    type               VARCHAR(20) NOT NULL,        -- government/enterprise/other
    industry           VARCHAR(100),
    region             VARCHAR(100),                -- 省市
    address            VARCHAR(500),
    level              VARCHAR(20) DEFAULT 'normal', -- key/normal/potential
    org_structure      JSONB,                       -- 加密存储
    relationship_score INTEGER DEFAULT 50,
    tags               JSONB DEFAULT '[]',
    notes              TEXT,                        -- 备注
    website            VARCHAR(500),
    last_contact_at    TIMESTAMP,
    next_follow_up_at  TIMESTAMP,
    created_at         TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at         TIMESTAMP NOT NULL DEFAULT NOW(),
    
    CONSTRAINT chk_customer_type CHECK (type IN ('government', 'enterprise', 'other')),
    CONSTRAINT chk_customer_level CHECK (level IN ('key', 'normal', 'potential'))
);

-- 索引
CREATE INDEX idx_customers_type ON customers(type);
CREATE INDEX idx_customers_region ON customers(region);
CREATE INDEX idx_customers_level ON customers(level);
CREATE INDEX idx_customers_follow_up ON customers(next_follow_up_at);
```

#### 6.2.3 contacts（联系人表）

```sql
CREATE TABLE contacts (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    customer_id  UUID NOT NULL REFERENCES customers(id) ON DELETE CASCADE,
    name         VARCHAR(100) NOT NULL,
    title        VARCHAR(100),                     -- 职位
    department   VARCHAR(100),
    role         VARCHAR(50),                      -- decision_maker/influencer/user/champion
    importance   VARCHAR(20) DEFAULT 'normal',     -- key/normal/low
    phone        VARCHAR(50),
    mobile       VARCHAR(50),
    email        VARCHAR(200),
    wechat       VARCHAR(100),
    birthday     DATE,
    preferences  JSONB,                            -- 个人偏好
    notes        TEXT,
    is_active    BOOLEAN DEFAULT TRUE,
    created_at   TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at   TIMESTAMP NOT NULL DEFAULT NOW(),
    
    CONSTRAINT chk_contact_role CHECK (role IN ('decision_maker', 'influencer', 'user', 'champion')),
    CONSTRAINT chk_contact_importance CHECK (importance IN ('key', 'normal', 'low'))
);

-- 索引
CREATE INDEX idx_contacts_customer ON contacts(customer_id);
CREATE INDEX idx_contacts_role ON contacts(role);
```

#### 6.2.4 interactions（交互记录表）

```sql
CREATE TABLE interactions (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    customer_id    UUID NOT NULL REFERENCES customers(id),
    project_id     UUID REFERENCES projects(id),
    contact_ids    JSONB DEFAULT '[]',             -- 参与联系人ID数组
    type           VARCHAR(30) NOT NULL,           -- call/meeting/email/wechat/visit/other
    subject        VARCHAR(300),
    content        TEXT,                           -- 原始内容（加密）
    summary        TEXT,                           -- AI整理的纪要
    key_points     JSONB,                          -- 关键要点
    sentiment      VARCHAR(20),                    -- positive/neutral/negative
    next_actions   JSONB,                          -- 下一步行动
    next_action_at TIMESTAMP,                      -- 下一步行动时间
    interaction_at TIMESTAMP NOT NULL,
    duration       INTEGER,                        -- 时长（分钟）
    location       VARCHAR(200),
    created_at     TIMESTAMP NOT NULL DEFAULT NOW(),
    
    CONSTRAINT chk_interaction_type CHECK (type IN ('call', 'meeting', 'email', 'wechat', 'visit', 'other'))
);

-- 索引
CREATE INDEX idx_interactions_customer ON interactions(customer_id);
CREATE INDEX idx_interactions_project ON interactions(project_id);
CREATE INDEX idx_interactions_time ON interactions(interaction_at DESC);
CREATE INDEX idx_interactions_next_action ON interactions(next_action_at) WHERE next_action_at IS NOT NULL;
```

#### 6.2.5 documents（文档表）

```sql
CREATE TABLE documents (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id      UUID REFERENCES projects(id),
    customer_id     UUID REFERENCES customers(id),
    name            VARCHAR(300) NOT NULL,
    original_name   VARCHAR(300),                  -- 原始文件名
    type            VARCHAR(50) NOT NULL,          -- bid/solution/report/contract/other
    file_path       VARCHAR(1000) NOT NULL,        -- 本地存储路径
    file_size       BIGINT,                        -- 文件大小（字节）
    file_ext        VARCHAR(20),                   -- 文件扩展名
    mime_type       VARCHAR(100),
    content_text    TEXT,                          -- 提取的文本内容
    ai_analysis     JSONB,                         -- AI分析结果
    ai_summary      TEXT,                          -- AI摘要
    embedding       vector(1536),                  -- PGVector向量
    version         INTEGER DEFAULT 1,
    is_latest       BOOLEAN DEFAULT TRUE,
    parent_id       UUID REFERENCES documents(id), -- 历史版本关联
    tags            JSONB DEFAULT '[]',
    created_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    
    CONSTRAINT chk_doc_type CHECK (type IN ('bid', 'solution', 'report', 'contract', 'policy', 'other'))
);

-- 索引
CREATE INDEX idx_documents_project ON documents(project_id);
CREATE INDEX idx_documents_customer ON documents(customer_id);
CREATE INDEX idx_documents_type ON documents(type);
CREATE INDEX idx_documents_latest ON documents(is_latest) WHERE is_latest = TRUE;

-- 向量索引（用于相似度检索）
CREATE INDEX idx_documents_embedding ON documents USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);
```

#### 6.2.6 knowledge（知识库表）

```sql
CREATE TABLE knowledge (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title          VARCHAR(300) NOT NULL,
    content        TEXT NOT NULL,
    summary        TEXT,                           -- 摘要
    category       VARCHAR(50) NOT NULL,           -- industry/solution/case/sales/lesson/other
    subcategory    VARCHAR(50),
    tags           JSONB DEFAULT '[]',
    keywords       JSONB DEFAULT '[]',             -- 关键词
    embedding      vector(1536),                   -- PGVector向量
    source_type    VARCHAR(30),                    -- case/experience/document/manual/import
    source_id      UUID,                           -- 来源对象ID
    source_name    VARCHAR(200),                   -- 来源名称
    author         VARCHAR(100),
    effective_date DATE,                           -- 生效日期
    expire_date    DATE,                           -- 过期日期
    view_count     INTEGER DEFAULT 0,
    use_count      INTEGER DEFAULT 0,              -- 使用次数
    rating         DECIMAL(2,1),                   -- 评分 1-5
    is_verified    BOOLEAN DEFAULT FALSE,          -- 是否已验证
    is_featured    BOOLEAN DEFAULT FALSE,          -- 是否精选
    created_at     TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at     TIMESTAMP NOT NULL DEFAULT NOW(),
```

```java
// 招标项目处理Pipeline
public class BidProjectPipeline {
    
    public PipelineResult execute(String documentId, String customerId) {
        
        Pipeline pipeline = Pipeline.builder()
            .name("BidProjectProcessing")
            
            // Step 1: 情报分析师解读招标文件
            .addStep(Step.builder()
                .agent(intelAgent)
                .action("analyzeBidDocument")
                .input(Map.of(
                    "documentId", documentId,
                    "focusAreas", List.of("评分标准", "技术要求", "资质要求"),
                    "includeRiskAnalysis", true
                ))
                .outputKey("bidAnalysis")
                .build())
            
            // Step 2: 知识管家检索相关案例
            .addStep(Step.builder()
                .agent(knowledgeAgent)
                .action("semanticSearch")
                .inputFrom(Map.of(
                    "query", "${bidAnalysis.projectType}",
                    "categories", List.of("case", "solution"),
                    "limit", 5
                ))
                .outputKey("relatedCases")
                .build())
            
            // Step 3: 文档写手生成方案初稿
            .addStep(Step.builder()
                .agent(docAgent)
                .action("generateSolution")
                .inputFrom(Map.of(
                    "bidAnalysis", "${bidAnalysis}",
                    "relatedCases", "${relatedCases}",
                    "templateType", "digital_government"
                ))
                .outputKey("solutionDraft")
                .needsApproval(true)  // 需要用户审核
                .build())
            
            // Step 4: 客户助理创建跟进计划
            .addStep(Step.builder()
                .agent(crmAgent)
                .action("suggestFollowUp")
                .input(Map.of(
                    "customerId", customerId,
                    "context", "${bidAnalysis.summary}"
                ))
                .outputKey("followUpPlan")
                .build())
            
            .build();
        
        return pipeline.execute();
    }
}
```

```typescript
// services/websocket.ts
class WebSocketService {
  private ws: WebSocket | null = null;
  private reconnectAttempts = 0;
  private maxReconnectAttempts = 5;
  private messageHandlers: Map<string, (data: any) => void> = new Map();
  
  connect(token: string): Promise<void> {
    return new Promise((resolve, reject) => {
      const wsUrl = `ws://localhost:8080/ws/agent?token=${token}`;
      this.ws = new WebSocket(wsUrl);
      
      this.ws.onopen = () => {
        this.reconnectAttempts = 0;
        resolve();
      };
      
      this.ws.onmessage = (event) => {
        const data = JSON.parse(event.data);
        this.handleMessage(data);
      };
      
      this.ws.onerror = (error) => reject(error);
      
      this.ws.onclose = () => this.handleDisconnect();
    });
  }
  
  chat(sessionId: string, content: string, context?: any) {
    this.send('chat', { sessionId, content, context });
  }
  
  stop(sessionId: string) {
    this.send('stop', { sessionId });
  }
  
  on(event: string, handler: (data: any) => void) {
    this.messageHandlers.set(event, handler);
  }
  
  private handleDisconnect() {
    if (this.reconnectAttempts < this.maxReconnectAttempts) {
      this.reconnectAttempts++;
      setTimeout(() => this.connect(''), 2000 * this.reconnectAttempts);
    }
  }
}

export const wsService = new WebSocketService();
```

## 十四、风险与应对

### 14.1 技术风险

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| AI模型不稳定 | 生成质量波动 | 多模型降级策略，结果审核机制 |
| PostgreSQL性能瓶颈 | 大数据量卡顿 | 索引优化，分表策略，定期清理 |
| 向量检索精度不足 | 知识检索不准 | 多路召回，混合检索策略 |
| 外部API变更 | 集成失效 | 版本锁定，监控告警，快速适配 |

### 14.2 业务风险

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 数据丢失 | 业务中断 | 自动备份，增量备份 |
| 招标网站反爬 | 监控失效 | 多数据源，降低频率，代理池 |
| IM平台封禁 | 通知失效 | 多通道备份，本地通知兜底 |

### 14.3 安全风险

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 本地数据泄露 | 敏感信息暴露 | 全量加密，安全删除 |
| API密钥泄露 | 费用损失 | 密钥链存储，使用监控 |
| 恶意输入 | AI输出异常 | 输入过滤，输出审核 |
